# 拟人化陪伴实施范围与验收标准

本功能在现有 Open WebUI 后端中增加独立陪伴模块，复用账号、模型连接和聊天界面。角色数据属于创建它的用户；同一用户与同一角色跨聊天共享心情和长期记忆。拟人化按聊天独立开关，新聊天可以采用用户默认值；主动搭话单独开关，每个角色只能绑定一个目标聊天。

## 第一版范围

- 多个可编辑角色：名称、人格、可选主动搭话模型。
- 聊天级开关；用户默认值只用于之后的新聊天，不回写已有聊天。
- 人格和当前心情注入；心情有界变化，按六小时半衰期回归基线 60。
- 独立人物画像、相处经验、短期状态、长期事实与待续话题。模型在回复后整理本轮内容，长期记忆记录来源消息，纠正事实保留旧版本并标记过时。
- 查看、修正、删除记忆，重置双方相处状态，删除角色。删除记忆同时清除派生画像与摘要，避免旧内容继续被引用。
- 主动搭话根据真实记忆和待续话题选择联系或沉默，限制清醒时段、最短间隔和每日生成次数；无论发送、沉默还是模型失败，已开始的生成都占用次数。
- 主动消息写入指定聊天，在线通过实时事件刷新，离线后再次打开可见。没有浏览器系统通知或外部渠道推送。

## 开关与数据边界

- 关闭模式保留记忆，但不再注入人格、读取陪伴记忆、整理新记忆或更新心情。
- 关闭主动目标聊天的拟人化模式或更换其角色，同时解除主动目标绑定；重新打开不会自动恢复主动搭话许可。
- 删除目标聊天后暂停主动搭话，不自动选择另一个聊天。
- 普通新聊天的原有功能保持不变。使用过拟人化的聊天，其历史仍含角色内容，因此停用通用用户记忆召回、原生记忆工具和自动整理，避免两套记忆互相污染。需要纯普通助手上下文时新建普通聊天。
- 临时聊天可使用人格，但不读取双方长期状态，不保存记忆，不更新心情，也不能作为主动消息目标。
- 配置以服务器保存值为准；旧客户端请求不能重新开启已关闭的聊天。
- 关闭操作不能撤回已经显示的消息或已经发生的模型调用。在途记忆结果与尚未投递的主动消息必须再次校验开关和状态版本。
- 同一用户消息重新生成或多模型同时回答，只允许一次成功的状态整理。并发编辑、重置、切换角色时，旧整理结果丢弃，不覆盖较新的状态。

## 实现位置

| 位置 | 职责 |
| --- | --- |
| `models/companions.py` | 角色、聊天绑定、用户默认值、已处理回合记录 |
| `routers/companions.py` | 所有权校验、配置与记忆管理 |
| `utils/companion_engine.py` | 心情衰减、记忆排序、上下文、主动策略约束 |
| `utils/companions.py` | 聊天接入、模型适配、后台整理和原子消息投递 |
| `chat/CompanionPanel.svelte` | 聊天开关、角色编辑、主动目标、记忆管理 |

聊天主流程只增加准备上下文与回复后整理接入点。后台循环独立于现有自动任务调度器，避免模型调用阻塞日历提醒。数据库条件更新负责任务领取；角色版本和聊天开关版本用于阻止过期结果提交。消息历史与规范化消息表在同一事务内更新。

## 验收标准

1. 用户 A 不能查看、更改或绑定用户 B 的角色、记忆或聊天。
2. 同一角色绑定两个聊天，双方状态一致；切换角色后不引用前一个角色的私有状态。
3. 修改新聊天默认值不改变已有聊天开关。
4. 关闭模式后，旧请求不能重新开启；在途整理不写入，在途主动消息不投递。
5. 临时聊天不产生持久陪伴状态；普通聊天不触发陪伴模型调用。
6. 同一用户消息重新生成、并发整理，最多形成一个处理记录，不重复增加心情或记忆。
7. 记忆删除、修正与相处状态重置后，在途旧整理不能恢复旧数据。
8. 每个角色最多有一个主动目标；重新绑定替换原目标，关闭目标聊天或删除角色后停止投递。
9. 安静时段、用户近期活跃、每日生成次数达到上限时不调用模型。
10. 多个后台实例竞争时，同一轮最多生成一次；投递前用户发来新消息则丢弃旧主动结果。
11. 主动消息同时出现在聊天历史和规范化消息表，在线刷新与离线重开均可读取。
12. 数据迁移可升级和回退；前端组件可编译；既有普通聊天接入点只做条件分支。

## 验证范围

`backend/tests/companion` 使用临时 SQLite 测试真实陪伴 ORM、路由与服务逻辑，替换宿主认证、聊天适配和模型调用。它验证业务隔离和并发约束，不等同于真实模型、完整服务器和浏览器端到端验收。部署前还需在测试环境完成普通聊天回归、真实模型记忆提取、在线主动消息展示和离线重开验收。

测试命令：`PYTHONPATH=backend pytest backend/tests/companion -q -o asyncio_default_fixture_loop_scope=function`。

## 当前限制

- 第一版采用有界本地记忆排序和模型决策，不包含 Aurabot 的完整模块市场、QQ/B 站能力或全部 purpose 引擎规则。
- 不提供 QQ、空间、外部评论、自动浏览、翻唱、表情包采集、分气泡和模拟打字。
- 后台使用服务器可访问的模型。仅存在于浏览器的直连模型不能承担离线整理与主动搭话。
- 默认主动搭话最多每日三次、至少间隔两小时，清醒时段为配置时区的 08:00–23:00。实际检查还受后台轮询与其他待处理角色影响。
- 每次符合条件的完整回复最多额外调用一次整理模型；主动生成另行计数。尚无跨角色的账户总费用预算。
- 每个角色最多保留 200 条长期记忆；短期摘要有效期两小时，画像和相处经验各有长度上限。
- 心情及画像属于可解释的角色状态和模型推断，并非对用户心理状态的诊断。模型推断可能出错，用户可查看和纠正。
