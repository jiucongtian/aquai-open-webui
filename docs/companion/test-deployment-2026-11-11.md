## 真实链路结果

使用两个合成普通账号、实际 `xiaosui_001` 模型与正常聊天接口，验证结果如下：

| 项目 | 实际结果 |
| --- | --- |
| 记忆提取 | 首轮提取并保存 4 条记忆，包括昵称“小蓝”、喜爱乌龙茶、画画计划 |
| 心情变化 | 初始 60 → 63，并保存变化原因 |
| 跨聊天共享 | 同角色的新聊天准确回答“小蓝～你最喜欢喝乌龙茶” |
| 角色隔离 | 另一角色回答不知道饮品和昵称，没有泄露前一角色记忆 |
| 用户隔离 | 第二账号修改第一账号角色被拒绝，返回 404 |
| 关闭开关 | 关闭后输入新昵称，角色 state 保持不变 |
| 单一主动目标 | 依次绑定两会话后，目标仅为后绑定会话 |
| 后台主动消息 | 自然运行的 worker 调用真实模型，原子保存消息，接口读取及浏览器均看到“画画计划进展得怎么样” |
| 关闭解绑 | 关闭目标会话拟人化后，主动目标为空 |
| 用户默认值 | 浏览器开启角色并保存默认值，刷新后角色和开关保留，数据库一致 |

为缩短等待，仅将合成角色的闲置时间与任务到期时间调整为已到期；没有直接调用投递函数，生成、持久化、调度与读取均走真实服务。安静时段、重试预算、竞态与临时聊天等边界以自动化测试为证，未声称每项均通过浏览器实测。

## 权限与数据清理

测试发现现有普通用户模型配置可列出 `xiaosui_001`，但其底层 `deepseek-flash` 读取权限不足，真实调用被拒绝。用户明确批准后，仅为合成验收账号临时添加读取权限；未扩大现有用户权限。真实用户仍需要具有相应模型权限才能使用对话与主动搭话。

清理检查发现原用户删除流程未覆盖新增陪伴数据，因此补上同事务清理并增加回滚、用户隔离测试。最终版本通过正常删除用户接口清理合成账号，数据库核验以下残留均为 0：user、auth、chat、companion、companion_chat、companion_preference、companion_turn、access_grant。临时模型授权已撤销，服务器及本机测试凭据文件已删除，无遗留主动目标。

安全验收报告保留在 `/opt/open-webui-test/data/companion-verification-report.json`，只含合成数据，不含凭据。
